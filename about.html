Simple File Encryptor 2.0

Private file encryption, kept simple.

Encrypt and decrypt files locally in your browser with Argon2id and AES-256-GCM. No uploads, accounts, cloud storage, or server-side processing.

Version 2.0 features:

🔐

Argon2id

Password-based keys are derived with a local Argon2id implementation based on RFC 9106.

🛡️

AES-256-GCM

Authenticated encryption protects both the file contents and the SFE2 encryption header.

📦

Up to 1 GB

The application accepts individual files up to 1 GB, subject to the memory available to your browser.

📁

Files & folders

Encrypt individual files or a folder selection. Multiple files are packaged into a ZIP archive.

⚡

Fully local

File data and passwords stay inside your browser while encryption or decryption is running.

🌐

Offline-ready

The release contains its runtime code locally, so no CDN, account, or internet connection is required after loading.

How encryption works

  1. Select your file. The browser reads the selected data locally. Nothing is uploaded.
  2. Enter a password. The password is passed to Argon2id together with a newly generated random salt.
  3. Derive the encryption key. Argon2id produces a 256-bit key using the parameters stored in the SFE2 header.
  4. Encrypt the file. AES-256-GCM encrypts the file with a fresh random 12-byte IV (nonce).
  5. Authenticate the metadata. The complete SFE2 header is supplied to AES-GCM as additional authenticated data (AAD), so changing the header or ciphertext causes authentication to fail.
  6. Download the result. The encrypted data is returned to you as a file. The application does not send it to a server.

Cryptography details

Key derivationArgon2id
Argon2id passes (iterations)3
Parallelism4 lanes
Memory12–500 MiB, selectable
Derived key32 bytes / 256 bits
Salt16 random bytes per encrypted file
EncryptionAES-256-GCM
IV / nonce12 random bytes per encrypted file
Authentication tag128 bits

Higher Argon2id memory settings make password guessing more expensive, but they also use more RAM. The default is 64 MiB. Choose a setting your device can comfortably handle.

Salt, IV and iterations explained

Salt

A salt is random data added to password-based key derivation. Every encrypted file gets its own 16-byte salt. This means the same password produces a different derived key for different files and prevents attackers from reusing precomputed password guesses across files.

IV / nonce

The 12-byte IV (initialization vector, also called a nonce for AES-GCM) is randomly generated for every encrypted file. It does not need to be secret, but it must be unique for a given AES-GCM key. It is stored in the SFE2 header so the file can be decrypted later.

Iterations / passes

Argon2id uses 3 passes over its memory-filled working state. Combined with the selected memory cost and 4 lanes of parallelism, this deliberately makes password guessing more resource-intensive than a simple fast hash.

The SFE2 file format

New encrypted files use the SFE2 format. Its authenticated header records the version, Argon2id settings, salt and IV, followed by the AES-GCM ciphertext and authentication tag.

SFE2 | version | KDF | memory | passes | parallelism | salt | IV | ciphertext + tag

Because the header is authenticated as AES-GCM AAD, an attacker cannot silently change the recorded encryption parameters without causing decryption to fail.

Privacy & limitations

  • Your files are processed locally in the browser.
  • Your password is not stored or transmitted by the application.
  • There are no accounts, cloud uploads, advertisements, analytics, or tracking built into the application.
  • Files up to 1 GB are accepted. Large files and high Argon2id memory settings can require substantial RAM and may be limited by the browser or device.
  • A forgotten password cannot be recovered. Keep a secure backup of important encrypted files and their passwords.
  • This project has not undergone an independent cryptographic security audit; the browser, operating system, and release files remain part of the security boundary.
